System architecture

Boxes only aim and ping; every decision is made on the laptop.

  • Diagram: 3 boxes (ESP32-WROOM-32E, SG90 servo, HC-SR04) → phone hotspot, UDP → laptop tracker → game display.
  • One measurement cycle: AIM → READY → FIRE → RANGE.
  • Only one box pings at a time, so the boxes do not hear each other's echoes.

V1: how the two-servo tracker works

Two bearings, two ranges, one point.

  • Both servos aim at the same target point (θ₀, θ₁), then both boxes ping.
  • Position = forward intersection of the two range circles, plus the 0.18 m body radius.
  • Four acceptance gates: a real intersection, inside the field, no implausible jump, ranges not stale.

05

V1 teardown: where it failed

On the official 1.5 m field, V1 showed a dot only 14 % of the time.

  • Every fix needs both echoes at once. One miss from either box means no position (17.6 losses/min).
  • Edges are out of reach. A player near one box is more than 1.7 m from the other, beyond reliable HC-SR04 range (example 2).
  • No one-box fallback. Partial information is thrown away.
  • On the 1.0 m bench (22 Sep) the same code reached 75 %. The failure is the geometry at full width, not a code bug.

Why V1 fails statistically, and why reacquire time is set by the ping schedule, not the servo.

Ruggedization and secondary features

Tighter tolerances in firmware, wiring and set-up.

  • Firmware: same pins on every box; build named by box position; aims clamped to the servo travel; servo ramp 150°/s so a large move does not rock the box.
  • Calibration: lost READY re-requested every 0.3 s; sweeps went from 0 of 3 completed to 111/111 pairs in 30 s.
  • Set-up: level and straighten each box before calibration (box 1 echo rate 35 % → 85 %).
  • Network: phone hotspot only, because university Wi-Fi blocked UDP.
  • Secondary feature: dead-zone buzzer box with retry, for the safety requirement.
  • UN SDG link: low-power ESP32 parts, components returned unmodified with no solder (R10), reusable rechargeable cells.

Worked calculations

Geometry used throughout: origin on the wall at the left edge of the field, x to the right, y away from the wall. V1 boxes at s₀ = (0, 0.2) and s₁ = (1.5, 0.2), so baseline b = 1.5 m and sensor line y_s = 0.2 m. Body radius R = 0.18 m.

Example 1 · slide 04

V1 position from two ranges

Player centre at (0.40, 1.20) m. Each HC-SR04 measures to the body surface, so the tracker adds R to get the distance to the centre.

Bearings the servos are sent to: θ₀ = atan2(1.20 − 0.20, 0.40 − 0) = 68.2° θ₁ = atan2(1.20 − 0.20, 0.40 − 1.50) = 137.7° Measured (surface) ranges: d₀ = 0.897 m d₁ = 1.307 m Centre ranges r = d + R: r₀ = 1.077 m r₁ = 1.487 m
x = (r₀² − r₁² + b²) / (2b) = (1.160 − 2.210 + 2.250) / 3.0 = 1.200 / 3.0 = 0.400 m h = √(r₀² − x²) = √(1.160 − 0.160) = 1.000 m y = y_s + h = 0.20 + 1.00 = 1.200 m

Recovered position (0.400, 1.200) m, equal to the true position. All four gates pass: h² > 0, inside the field, no jump, fresh ranges.

Example 2 · slide 05

Why V1 loses the player at the edge

Player at the left edge, deep in the field, (0.10, 1.80) m.

r₀ = √(0.10² + 1.60²) = 1.603 m within 1.7 m reach r₁ = √((0.10 − 1.50)² + 1.60²) = √(1.96 + 2.56) = 2.126 m beyond 1.7 m reach

Box 1 gets no reliable echo, so V1 has no fix at all. V2 shows a one-box fix from box 0, and the current MVP adds the middle box at x = 0.75 m, which is 1.71 m away.

Example 3 · slide 08

Position error from range error

Differentiate the intersection formulas. With b fixed and h = y − y_s:

∂x/∂r₀ = r₀ / b ∂x/∂r₁ = −r₁ / b ∂y/∂r₀ = r₀ (1 − x/b) / h ∂y/∂r₁ = x r₁ / (b h) σx = σr · √(r₀² + r₁²) / b σy = σr · √( (∂y/∂r₀)² + (∂y/∂r₁)² )

At the example 1 point, with a range noise of σr = 1 cm per sensor:

σx = 1 cm × √(1.160 + 2.210) / 1.5 = 1 cm × 1.224 = 1.2 cm ∂y/∂r₀ = 1.077 × (1 − 0.267) / 1.0 = 0.790 ∂y/∂r₁ = 0.40 × 1.487 / (1.5 × 1.0) = 0.396 σy = 1 cm × √(0.790² + 0.396²) = 1 cm × 0.884 = 0.9 cm

Predicted 1.2 cm in x and 0.9 cm in y. Measured standing jitter on 22 Sep (bench-live15): 2.2 cm and 0.7 cm. x error is larger because both range errors add into x; the body moving adds the rest.

Example 4 · slide 08

Both echoes vs any echo

Simple model: each box returns a usable echo with probability p, independently. Echo rates from swarm-run3: p₀ = 0.75, p₁ = 0.74.

V1 needs both: P = p₀ · p₁ = 0.75 × 0.74 = 0.555 V2 needs one: P = 1 − (1 − p₀)(1 − p₁) = 1 − 0.25 × 0.26 = 0.935

Even in the middle of the field, requiring both echoes drops the chance of a fix from 94 % to 56 % per cycle. Add the edge cases from example 2 and V1 falls to the measured 14 %. V2 measured 89 %, close to the 94 % model.

Example 5 · slide 08

Reacquire time budget

Only one box may ping at a time. A searching ping takes T_slot = 0.10 s (25 ms echo timeout, 65 ms acoustic guard, 10 ms poll). With N = 3 boxes:

T_step = N · T_slot = 3 × 0.10 s = 0.30 s per step, per box T ≈ T_start + n · T_step + T_confirm, T_confirm = T_step
Box 2, column 1 → 3T_startSteps nn · T_stepT_confirmModelSimulator
Before: jitter, then 5° sweep1.30 s61.80 s0.30 s3.40 s3.64 s
After: search, 15° steps0.50 s20.60 s0.30 s1.40 s1.44 s

The model lands within 0.25 s of the simulator. The step period is fixed by the ping schedule, so the only ways to go faster are to start the search sooner and to take bigger steps. That is exactly change C5.
